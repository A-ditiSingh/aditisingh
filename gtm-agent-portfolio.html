The Design Problem

Data responses require more than a good summary

A text-based agent response needs to summarize sources well. A data-based response has to do more: it needs to present data in the right format, and it needs to give users the context to understand how that data was derived.

Without both, users can't tell if the answer is right. They either overtrust it or ignore it.

Present data in an appropriate format — not all data reads the same way; the wrong format creates confusion even when the data is correct
Surface the derivation context — users need to understand the filters, assumptions, and scope the agent applied to arrive at the answer
Allow easy requery — if the answer isn't quite right, the path to refining it should be obvious and low-friction

Text vs. data response format — different jobs, different components

Four response types — Table, List, Chart, Single Stat

Response Format

Four response types. Each with a distinct job.

The starting point for a data response is choosing the right format. We defined four types based on the shape of the question — not just the shape of the data.

01
Single stat
The answer is a direct fact or single number. No additional structure needed.
02
List
Query is scoped enough that additional metadata adds no value. Names, not measurements.
03
Table
Ranked or comparative answer where the metric value matters — users need to act on specific values.
04
Chart
The shape of the data is the answer — a trend, spike, plateau, or anomaly.

The prompt as design spec — decision rules for categorizing questions into response types

Design Insight

The prompt is the design spec

Defining the four types was the easy part. Getting the agent to choose correctly required specifying decision logic precisely enough that the model could apply it consistently.

That meant writing detailed decision rules — when to use a table over a list, how to distinguish a trend question from a ranking question — and encoding them directly into the prompt. The prompt became the design deliverable.

Key insight

In agentic design, the prompt is the design spec. If you can't articulate a decision rule clearly enough to write it down, the agent can't apply it. The act of writing the prompt forces design rigor.

BeforeFormat chosen by default — usually a text summary regardless of the question type
AfterFormat chosen by explicit decision rules encoded in the prompt

Key Learnings

What this product taught me

Learning 01
The prompt is the design spec
In agentic product design, you can't just design the UI — you have to design the agent's decision logic too. Writing precise decision rules for format selection forced a clarity that visual mockups alone never require.
Learning 02
Trust is a design deliverable
For data-based AI responses, the answer alone isn't enough. Users need to see how the dataset was derived to decide whether to act on it. Surfacing derivation context — filters, scope, assumptions — is as important as the data itself.

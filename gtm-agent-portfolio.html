Agentic design for data

When an AI agent answers a question with data, the design challenge isn't just what to show — it's how to present it, how to build trust, and how to help users understand exactly where the answer came from.

As design lead for analytics, I took on GTM Agent because the questions GTM teams ask — about content performance, rep activity, pipeline — almost always warrant a data-based response, not just a text summary.

The Shift

Before: wayfinding. After: a different design problem entirely.

Before AI, users had to navigate to the right place themselves — scorecard for overviews, report builder for datasets. My job was to make that wayfinding as frictionless as possible.

After AI, the user asks a question. The agent looks through the platform and composes the answer. My job changed completely.

The Design Problem

Data responses require more than a good summary

A text-based agent response needs to summarize sources well. A data-based response has to do more: it needs to present data in the right format, and it needs to give users the context to understand how the agent derived that data.

Without both, users can't tell if the answer is right. They either overtrust it or ignore it.

Present data in an appropriate format — not all data reads the same way; the wrong format creates confusion even when the data is correct
Surface the derivation context — users need to understand the filters, assumptions, and scope the agent applied to arrive at the answer
Allow easy requery — if the answer isn't quite right, the path to refining it should be obvious and low-friction

Text vs. data response format — different jobs, different components

Four response types — Table, List, Chart, Single Stat

Response Format

Four response types. Each with a distinct job.

The starting point for a data response is choosing the right format. We defined four types based on the shape of the question — not just the shape of the data.

01
Single stat
The answer is a direct fact or single number. No additional structure needed.
02
List
Query is scoped enough that additional metadata adds no value. Names, not measurements.
03
Table
Ranked or comparative answer where the metric value matters — users need to act on specific values.
04
Chart
The shape of the data is the answer — a trend, spike, plateau, or anomaly.

The prompt as design spec — decision rules for categorizing questions into response types

Design Insight

The prompt is the design spec

Defining the four types was the easy part. To get the agent to choose correctly, I had to specify decision logic precisely enough that the model could apply it consistently.

I wrote detailed decision rules — when to use a table over a list, how to distinguish a trend question from a ranking question — and encoded them directly into the prompt. The prompt became the design deliverable.

Key insight

In agentic design, the prompt is the design spec. If you can't articulate a decision rule clearly enough to write it down, the agent can't apply it. The act of writing the prompt forces design rigor.

AfterExplicit decision rules I encoded in the prompt drive format choice

Phase 01 — Query

The agent interprets the question. Humans refine the filters.

The agent parses the user's question into a structured query, but it doesn't execute blindly. Two human-in-the-loop components give users control before the data runs.

01

Filter proposal

The agent proposes filters based on the question (time range, scope, exclusions). Users accept, adjust, or reject before query execution.

02

Entity disambiguation

If the query references something ambiguous ("Show me top reps" but the user has access to 15 teams), the agent asks for clarification rather than guessing.

Phase 03 — Action

Selecting a row surfaces the next logical step

The response table isn't a dead artifact. When a user clicks a row, that item becomes the context for what happens next. The UI surfaces one clear, contextual action tied to the selected item—not a generic menu, but a specific outcome shaped by the data.

If a rep shows low activity completion, the action might be to view their coaching history. If a content piece has high engagement, the action might be to check replication patterns. The action flows from the insight.

The full loop — Query to Response to Action

Putting It Together

From insight to action in three phases

The three phases form a coherent loop. The user doesn't just ask a question and receive a passive answer. They refine the query, evaluate the response in context, select what matters to them, and move directly into action—all without leaving the conversational interface.

01

Query

User asks a question; agent proposes filters and disambiguates ambiguity

02

Response

Agent returns the answer in the appropriate format (table, chart, list, stat), with full context on how it derived the dataset

03

Action

User selects a specific item or insight; the UI surfaces a contextual next step they can take immediately

Key Learnings

What this product taught me

Learning 01
The prompt is the design spec
In agentic product design, you can't just design the UI — you have to design the agent's decision logic too. Writing precise decision rules for format selection forced a clarity that visual mockups alone never require.
Learning 02
Trust is a design deliverable
For data-based AI responses, the answer alone isn't enough. Users need to see how the agent derived the dataset to decide whether to act on it. Surfacing derivation context — filters, scope, assumptions — is as important as the data itself.

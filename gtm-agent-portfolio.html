Agentic design for data

When an AI agent answers a question with data, the design challenge is how to present that data in the right format and give users enough context to evaluate whether the answer is correct.

The Shift

Before AI, the design problem was wayfinding. After AI, it shifted to trust and clarity.

Before AI, users had to navigate to the right surface themselves — scorecard for overviews, report builder for datasets. The design focus was reducing that wayfinding friction. After AI, the user asks a question and the agent composes the answer. The design focus shifted to making the response trustworthy and understandable.

The Design Problem

Data responses require format selection and derivation context, not just a summary

A text-based agent response needs to summarize sources well. A data-based response has additional requirements: the data needs to be presented in the right format, and users need enough context to understand how the agent derived it. Without both, users cannot evaluate whether the answer is correct and are likely to either overtrust or dismiss it.

Present data in an appropriate format — not all data reads the same way; the wrong format creates confusion even when the data is correct
Surface the derivation context — users need to understand the filters, assumptions, and scope the agent applied to arrive at the answer
Allow easy requery — if the answer isn't quite right, the path to refining it should be obvious and low-friction

Text vs. data response format — different jobs, different components

Four response types — Table, List, Chart, Single Stat

Response Format

Four response types, each suited to a different kind of question

The starting point for a data response is choosing the right format. We defined four types based on the shape of the question — not just the shape of the data.

01
Single stat
The answer is a direct fact or single number. No additional structure needed.
02
List
Query is scoped enough that additional metadata adds no value. Names, not measurements.
03
Table
Ranked or comparative answer where the metric value matters — users need to act on specific values.
04
Chart
The shape of the data is the answer — a trend, spike, plateau, or anomaly.

The prompt as design spec — decision rules for categorizing questions into response types

Design Insight

Getting the agent to choose the right format required writing explicit decision rules in the prompt

Defining the four types was straightforward. Getting the agent to apply them consistently required writing decision rules precise enough for the model to follow — when to use a table over a list, how to distinguish a trend question from a ranking question. I encoded these rules directly into the prompt, which became the primary design deliverable for this part of the work.

BeforeAgent defaulted to a text summary regardless of the question type
AfterExplicit decision rules I encoded in the prompt drive format choice

Phase 01 — Query

The agent parses the question into a structured query, with two human-in-the-loop checkpoints before execution

The agent proposes a structured query from the user's question, but does not execute it automatically. Two checkpoints give users the opportunity to review and adjust before the data runs.

01

Filter proposal

The agent proposes filters based on the question (time range, scope, exclusions). Users accept, adjust, or reject before query execution.

02

Entity disambiguation

If the query references something ambiguous ("Show me top reps" but the user has access to 15 teams), the agent asks for clarification rather than guessing.

+Action from table row

Action phase — user selects a row, actionable next step appears

Phase 03 — Action

Selecting a row surfaces a contextual next step tied to that item

When a user clicks a row in the response table, the UI surfaces one action specific to the selected item — not a generic menu. The action is determined by the data. If a rep shows low activity completion, the action might be to view their coaching history. If a content piece has high engagement, the action might be to check replication patterns.

+Full three-phase loop

The full loop — Query to Response to Action

Putting It Together

The three phases connect questioning, response, and action in a single flow

The three phases form a connected loop. The user refines the query, evaluates the response in context, selects a specific item, and moves into action — all within the conversational interface.

01

Query

User asks a question; agent proposes filters and disambiguates ambiguity

02

Response

Agent returns the answer in the appropriate format (table, chart, list, stat), with full context on how it derived the dataset

03

Action

User selects a specific item or insight; the UI surfaces a contextual next step they can take immediately

Key Learnings

What this product taught me

Learning 01
In agentic product design, the prompt is the design deliverable
Designing the agent's decision logic required the same precision as designing the UI. Writing explicit decision rules for format selection forced a level of clarity that visual mockups alone don't require.
Learning 02
For data-based AI responses, derivation context is as important as the data
Users need to see the filters, scope, and assumptions the agent applied to decide whether the answer is correct. Surfacing that context is a core part of the design, not secondary to it.
